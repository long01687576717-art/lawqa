# 劳动法知识库问答系统

一个基于 **DeepSeek 大模型 + 本地向量检索** 的 RAG（检索增强生成）问答系统：收录中国劳动法条与劳动争议案例，用户提问后，系统检索出最相关的法条和相似案例，交给大模型生成带出处的回答。

## 功能

- 🔍 语义检索：向量检索 + 关键词检索混合，自动匹配最相关的法条与案例
- 💬 智能问答：调用 DeepSeek 生成回答，并引用具体法条与案例
- 📖 法规库：15 部法律法规共 715 条，均为官方原文（法律、行政法规、司法解释取自国家法律法规数据库，部门规章取自中国政府网、司法部、人社部官网），详见下方「法规收录范围」
- ⚖️ 案例库：217 个官方公开案例（最高法指导性案例、公报案例、人社部/最高法典型案例，北京、天津、河南、广东、贵州、吉林、陕西、福建等省级法院与人社部门联合发布的典型案例），原文逐字收录
- 🧭 方向标签：案例按 28 个细分方向打标签，提问时自动匹配对应方向的案例

## 快速开始（Windows）

1. **申请 DeepSeek API Key**：打开 <https://platform.deepseek.com>，注册后创建 API Key（按量计费，很便宜）。

2. **配置 Key**：复制 `.env.example` 为 `.env`，把里面的 `DEEPSEEK_API_KEY=sk-xxxx` 改成你的 Key。

3. **启动**：双击 `run.bat`（首次会自动安装依赖 + 下载约 100MB 中文向量模型，耐心等待几分钟）。

4. **使用**：浏览器打开 <http://127.0.0.1:8000>，输入问题即可。

> 手动启动（不用 bat）：
> ```bash
> pip install -r requirements.txt
> python app.py
> ```

## 如何添加案例

1. **只收录真实、可核验的官方公开案例**（最高人民法院指导性案例、公报案例、最高法/人社部联合发布的典型案例、省级法院/人社部门官网发布的典型案例），各段内容逐字粘贴原文，不改写、不补写。
2. 每个案例存成一个 `.txt` 文件，放进 `data/_cases_raw/`，按 `data/_cases_raw/_模板.txt` 的格式标注：

```text
【标题】案例名称
【案号】（2011）杭滨民初字第885号          （没有可不写）
【法院】浙江省杭州市滨江区人民法院          （没有可不写）
【关键词】劳动合同 单方解除                （没有可不写）
【案情】基本案情原文，可多行
【裁判结果】裁判结果 / 处理结果原文
【裁判要点】裁判要点 / 裁判要旨原文        （没有可不写）
【案例分析】案例分析 / 裁判理由原文        （没有可不写）
【典型意义】典型意义原文                  （没有可不写）
【标签】单位解除合同 规章制度与违纪        （空格分隔，取值见 case_tags.py 的 TAGS）
【来源】发布机构（发布日期）https://原文链接
```

   - 以 `_` 开头的文件会被忽略（模板文件即如此）。
   - `【标签】` 不写时按标题和关键词自动识别；写了未知标签，解析脚本会报错提示。

3. 运行解析脚本，生成/更新 `data/cases.json`：

```bash
python scripts/build_cases.py
```

4. **重启服务**（关掉重开 `run.bat`；线上 Streamlit 版需在后台手动 Reboot），即可检索到新案例。

## 法规收录范围

| 层级 | 法规 | 来源 |
|---|---|---|
| 法律 | 劳动法、劳动合同法、社会保险法、劳动争议调解仲裁法、就业促进法 | 国家法律法规数据库 |
| 行政法规 | 劳动合同法实施条例、工伤保险条例、女职工劳动保护特别规定、职工带薪年休假条例 | 国家法律法规数据库 |
| 司法解释 | 最高法关于审理劳动争议案件适用法律问题的解释（一）（二） | 国家法律法规数据库 |
| 部门规章 | 工资支付暂行规定、最低工资规定、企业职工带薪年休假实施办法、劳务派遣暂行规定 | 人社部 / 中国政府网 / 司法部官网 |

- 只收现行有效版本；地方性法规、规章（如各地产假、最低工资标准）不在收录范围内，回答时只提示法规名称。
- **分层检索**：劳动法、劳动合同法作为核心法律单独排名取前 5 条，其他配套法规另取前 4 条，避免配套条文挤占核心条文；关联条文扩展时，同层级关联优先，跨层级关联（如实施条例引用劳动合同法）另给名额。
- 更新法规：`python scripts/build_laws.py`（联网抓取，已留档的读本地；加 `--offline` 只用留档重新解析），然后运行 `python scripts/build_citation_index.py`。

## 案例如何匹配到问题

- **大方向**：查询改写给出 12 个核心场景之一（加班费、未签劳动合同、违法解除……），对应到若干标签。
- **细分标签**：按问题里的关键词在本地识别标签（如「调岗」「离职证明」「offer」），不经大模型，不影响法条召回。
- 两者任一与案例标签重合即为候选，再按「全文 BM25 相关度 + 标题相关度（典型案例标题多为裁判要旨）+ 标签稀有度加分」排序，最多取 3 个；文字上几乎不相关（BM25 低于下限）的淘汰，宁缺毋滥。
- 与劳动法无关的问题（改写为「无」且识别不出任何标签）不返回案例。

## 评测

评测脚本在 `scripts/eval/`，可在任意目录运行，结果写入 `scripts/eval/results/`。

| 脚本 | 作用 | 是否调用大模型 |
|---|---|---|
| `law_eval.py` | 法条召回离线评测（原 30 题 / 新 15 题 / 企业 64 题），复用已记录的改写结果 | 否 |
| `case_eval.py` | 案例匹配离线复查，对比筛选前后变化 | 否 |
| `regression_cases.py` | 53 题真实回归：改写 + 检索 + 生成，检查法条召回与案例引用 | 是 |
| `coverage_eval.py` | 企业 HR 64 题覆盖评测：检查是否需要库外法规、能否匹配到案例 | 是 |
| `testset.py` | 测试题集与目标法条 | — |

```bash
python scripts/eval/law_eval.py      # 改检索参数后先跑这个，几十秒出结果
python scripts/eval/case_eval.py
```

`legacy/` 是 2026-09-27 之前几轮的旧脚本，仅留档，配合 `docs/测试报告/` 查阅，不保证能复现当时结果。

## 数据来源说明

- 法规文本全部取自官方渠道，每条法条都附官方原文链接与施行日期；解析时逐条校验条号连续、内容与原文逐字一致。
- 案例全部来自官方公开渠道，每个案例的【来源】都写明发布机构、发布日期和原文链接；各段内容与原文逐字一致（收录时已用脚本逐段比对）。不要虚构案号或案情。

## 技术栈

- 后端：Python + FastAPI + Uvicorn
- 大模型：DeepSeek（OpenAI 兼容接口，`deepseek-chat`）
- 检索：`fastembed` + `BAAI/bge-small-zh-v1.5`（ONNX，无需 PyTorch）+ `jieba` BM25 兜底
- 存储：JSON 文件，无需数据库
